What was built

A complete, reproducible on-premises deployment package for the three-service application stack — API, PostgreSQL database, and clinician dashboard — targeting hospital IT teams where cloud hosting is not permitted. The package ships three containerized services, a single-host Docker Compose stack for development/pilots, and production Kubernetes Helm charts.

Research backing

The technology research cycle identified containerization as a top infrastructure improvement:

“Add containerized deployment (Docker) for reproducible environments and easier on-prem hospital installs.”

The product is an ICU pressure-relief mattress monitoring system handling patient data, so the package is HIPAA/GDPR-aligned by construction (non-root containers, secrets via K8s Secret/ConfigMap split, TLS at ingress, encrypted volumes, audit-logging guidance, and backup encryption guidance).

Technical approach

  • Dockerfiles per service — minimal, non-root, with healthchecks.
  • docker-compose for dev — one command (docker compose up -d --build) for a full local stack.
  • Helm charts for Kubernetes — ConfigMap + Secret for config, PVCs for state, optional Ingress, optional backup CronJob, autoscaling values.
  • Config via env/ConfigMaps — every setting flows through env vars; non-secret config in a ConfigMap, the DB password in a Secret (never in the Deployment spec).
  • Backup & upgrade scripts — pg_dump backups with retention, restore, and rolling upgrade helpers.
  • Single entry point — the dashboard nginx proxies /api and /health to the API, so compose and Kubernetes share one traffic shape.

Risks & tradeoffs

RiskMitigation
On-prem support burdenReproducible images + pinned versions + healthcheck/upgrade scripts reduce drift; docs give hospital IT a single runbook.
Environment drift across hospitalsSingle Helm chart and env-only configuration; versioned image tags; CI-built images.
Single-replica DB (no HA)Documented as a tradeoff; a StatefulSet/HA path and off-host backups are the recommended next step.
Schema duplication (compose vs Helm)Both paths ship the same 001_schema.sql; migrations are a documented future step.
Clinical safety / FDA SaMD scopeExplicitly noted in docs/SECURITY.md that this is a deployment reference, not a validated medical device.

How to run

cp .env.example .env
docker compose up -d --build     # dashboard: http://localhost:8081

helm upgrade --install pressure-mattress deploy/helm/pressure-mattress \
  --namespace pressure-mattress --create-namespace \
  --set postgres.password="$(openssl rand -base64 32)"

See README.md, docs/ON_PREM_DEPLOYMENT.md, and docs/SECURITY.md for full details.
